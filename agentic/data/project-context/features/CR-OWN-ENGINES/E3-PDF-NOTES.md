# E3 PDF engine: design notes (2026-10-24)

These are the ideas and lessons from surveying `lib/src/engines/pdf/` (pdrx family) under the idea-level amendment in DECISIONS.md. They are not code to copy. Web is out of scope (DECISIONS Q1).

## What the app and kit actually need
- **Opening:** open a file, retrying while it asks for a password. A cancelled password closes the reader.
- **Pages:** page count and sizes, with rotation applied.
- **Layouts:** continuous vertical and horizontal.
- **Zoom:** pinch, double-tap and wheel, plus zoom in/out and fit-width. Jump to page.
- **Callbacks:** a page-changed callback (it includes the initial page), a ready callback and tap handling.
- **Errors:** an error widget.
- **Search:** text per page with character boxes, incremental search painting highlights, next/previous match, and the scanned-PDF text-layer probe.
- **Thumbnails:** small page images for the in-reader strip and for thumbnails saved to disk.
- **Night mode:** the app inverts colours with a `ColorFilter`.
- **Not used:** text selection, forms editing, saving, outline, URI/asset/data sources. Link taps are open question L1 below.

## Native binary (decided)
- **Source:** bblanchon/pdfium-binaries **`chromium/8086`** (2026-10-05, PDFium 157.0.8086), the newest release older than two weeks.
- **Platforms:** android-{arm,arm64,x64,x86}, ios-device-arm64, ios-simulator-{arm64,x64}, mac-{arm64,x64}, linux-{x64,arm64}, win-{x64,arm64}.
- **Verification:** every archive's SHA-256 is pinned in the hook (recorded on 2026-10-24). A cached file is re-verified, never trusted blindly.
- **Hook:** one build hook for every platform, iOS included, because iOS archives ship a dylib. That replaces the old CocoaPods/SwiftPM `darwin/` xcframework, the iOS-only link hook and `ffiPlugin`.
- **Bindings:** `@Native(assetId: 'package:open_reader_kit/libpdfium')`, generated by **our own `ffigen` config** from `fpdfview.h`, `fpdf_text.h` and `fpdf_doc.h`. Only the functions below are included, against the old generated file's 14k lines. No hand-parsing of `native_assets.yaml`.
- **Licences:** NOTICE credits PDFium (BSD-3) and the third-party licences that ship inside the archive (`licenses/`).

## Minimal PDFium surface
- **Setup:** `FPDF_InitLibraryWithConfig`, `FPDF_DestroyLibrary`.
- **Opening:** `FPDF_LoadDocument` (path, password), `FPDF_LoadMemDocument64`, `FPDF_GetLastError`, `FPDF_CloseDocument`.
- **Pages:** `FPDF_GetPageCount`, `FPDF_LoadPage`, `FPDF_ClosePage`, `FPDF_GetPageWidthF`, `FPDF_GetPageHeightF`, `FPDF_GetPageBoundingBox` (crop-box offset).
- **Rendering:** `FPDFBitmap_CreateEx` (BGRA), `FPDFBitmap_FillRect`, `FPDFBitmap_Destroy`, and `FPDF_RenderPageBitmap` with `FPDF_ANNOT` and `FPDF_LCD_TEXT` off.
- **Forms (optional):** `FPDFDOC_InitFormFillEnvironment` + `FPDF_FFLDraw`, so filled-in form values show.
- **Text:** `FPDFText_LoadPage`, `FPDFText_ClosePage`, `FPDFText_CountChars`, `FPDFText_GetUnicode`, `FPDFText_GetCharBox`.
- **Links (if L1 says yes):** `FPDFLink_LoadWebLinks` and the related calls.

## Threading (better than before)
- **One long-lived worker isolate per process** owns PDFium; nothing calls PDFium elsewhere. Requests are messages; replies carry results.
- **Last error read in the same call:** `FPDF_GetLastError` runs in the same worker call as the load and comes back with the result. The old code read it on the main isolate, which is wrong on Windows, where the error is per thread.
- **Priorities:** visible-page renders go before prefetch renders and thumbnails, and text and search requests aren't stuck behind a queue of renders. A request can be cancelled while still queued.
- **Handle reuse:** the worker keeps a small LRU of `FPDF_PAGE`/`FPDF_TEXTPAGE` handles per document. The old engine reopened them for every operation.
- **Pixels:** the worker renders into its own buffer and sends it back as `TransferableTypedData`, with no copy on the UI side. The UI decodes `bgra8888` through `ImageDescriptor.raw` (not `decodeImageFromPixels`, which never completes on failure).
- **Search in the worker:** text is extracted and matched in one call per page, returning match rects. The old engine extracted and matched on the UI isolate across many round trips.

## Viewer (better than before)
- **Lazy 2D layout** of pages (continuous vertical or horizontal) in PDF points, built only for what's visible. Zoom and pan use Flutter's own `InteractiveViewer`, not a 1.7k-line fork, or a slim custom transform.
- **Resolution:**
  - each page has a low-resolution base image (capped at about 2000 px)
  - when zoomed past the base, **fixed-size tiles at discrete zoom levels** are rendered for the visible region and cached; they're reused while panning instead of re-rendering the whole visible area
  - the cache has an LRU byte budget, evicting what's far from the viewport first
- **No side effects in `paint()`:** render requests come from layout and scroll changes, never from paint.
- **Page sizes:** all page sizes come in one worker call at open, so mixed-size documents don't jump. The old engine guessed and re-laid out progressively.
- **Current page:** keep the old engine's idea of the most visible page, made sticky so it doesn't flicker between pages.
- **Thumbnails:** `renderThumbnail(page, width)` renders the whole page scaled down. The old service rendered at 72 dpi and **cropped the top-left 160 px**.

## Edge cases to keep
- The crop-box offset applied to text and link rects.
- `/Rotate`, applied by PDFium (rotation 0 passed to the renderer).
- Huge pages capped.
- Null checks on page and bitmap creation, and renders that fail without crashing.
- Forms drawn after the page.
- A white background behind every page.
- Scale = zoom × devicePixelRatio.
- Character spacing from PDFium kept within sensible ratios when building the search text.

## Open question
- **L1:** should link taps inside PDFs (web links, in-document jumps) work? The old viewer had them on by default, but no app code relies on them. The default plan: support web links (http/https/mailto, as in Word) and in-document jumps.

## Plan
- **E3a: native layer and engine.**
  - the hook with pinned hashes
  - our own bindings
  - the worker with handle reuse and priorities
  - the engine API: open with password, page sizes, render region/tile, page text with boxes, search, thumbnail
  - tests that load the real dylib on the macOS host
- **E3b: viewer and switch.**
  - the viewer widget and controller, keeping the kit's `PdfDocumentController` contract
  - the app's thumbnail strip and thumbnail service
  - removing the pdfrx engine, the wasm assets, `darwin/`, the link hook and `ffiPlugin`
  - NOTICE
  - checks on the Android emulator and macOS
